

########################################################
Create a Google Cloud Project named, "agremotesensing" 
that has access to the earthengine-api (ie, Google Earth Engine)
########################################################

BASIC SCHEMATIC
-----------------
Step 1: Create a Google Cloud Project (The baseline container)
  │
  └───► Step 2: Enable Earth Engine on that Project (Unlocks the data)
         │
         └───► Step 3: Create a Service Account inside that Project (The robot user)
                │
                └───► Step 4: Generate & download the JSON Key (The local credential)

To assign a billing account to your Google Cloud Project, you need to link it via the Billing section of the Google Cloud Console


#######################
Step-by-Step Workflow
#########################
	* create your new Google Cloud Project
	* link it directly to your existing central billing account, 
	* enable Earth Engine, and 
	* extract your secure JSON service account key. 

Step 1: Create the Project and Link it to Your Cloud Billing Account
	a. Go to the Google Cloud Console
		https://console.cloud.google.com
		https://console.cloud.google.com/welcome?organizationId=0&supportedpurview=project,folder

	b. Welcome .... 
		clic "Create or Select a Project"

	c. Select a Name and "No Organization"

	d. Go to the Google Cloud Console Billing Account Management page.
		https://console.cloud.google.com/billing

	e. Clic on tab, "Your Projects"
		the new project should already be listed under the billing account

Step 2: Enable and Register Google Earth Engine
A newly-created project does not have access to Earth Engine by default; you must unlock the API and register your project’s intended use case. 
	a. Select your newly created project from the top blue project dropdown menu in the Cloud Console.
	   [https://console.cloud.google.com/welcome?project=agremotesensing]

	b. Use the top search bar to look for Earth Engine API (in Marketplace) click it, and then click the blue Enable 
	   button.

	c. Search "Earth Engine" and select "Earth Engine" (product)

	d. Register your GEE-enabled project 
		* registered Community / Noncommercial tier

	e. Go to the "Google Cloud Console IAM & Admin Service Accounts" page
	   [https://console.cloud.google.com/iam-admin/iam?project=agremotesensing]
	   Verify that your new project name is visible in the top blue navigation bar dropdown menu.

	f. clic "+ Create Service Account" button at the top
		* Service Account will use .json credentials

	g. In the Select a role dropdown filter, type Earth Engine and pick TWO roles:
		• "Earth Engine Resource Admin" (authority to manage data (Admin)
		* "Service Usage Consumer" (authority to run up a computing/billing)
		*  set the same TWO roles for marron.bruce.mx@gmail.com
		
	h. From the main list, click directly on the newly created Service Account email string
	   [bmarron18-ag@agremotesensing.iam.gserviceaccount.com]

	i. Navigate to the Keys tab at the top, select the Add Key button dropdown, and click Create new key.

	j. Leave the selection box ticked on JSON and hit Create

------------------------------------------------------------

	  a Google Cloud Project to access APIs via google-cloud-sdk
	* Compute Engine default service account (default name)
	* the default .json file can generate a token to be used to run API scripts IFF the 
	  GOOGLE_APPLICATION_CREDENTIALS environment variable is NOT set
	* Google-Managed Key (.json file): NOT AVAILABLE
	* Google-Managed Key has 2-year expiration window, the standard lifecycle for Google-managed keys (Google 
	  automatically rotates for you)

---------------------------------------------
(hard-coded) SERVICE ACCOUNT CREDENTIALS
----------------------------------------------
	* hard-coded credentials used by a Google Cloud Project to access APIs bypassing google-cloud-sdk
	* a downloaded .json file used to run API scripts by setting the GOOGLE_APPLICATION_CREDENTIALS 
	  environment variable in local computer
	* running Python script using a .json service account credential file to call "earthengine-api", entirely 
	  bypasses google-cloud-sdk credentials for that runtime. Your code communicates directly with the Earth Engine servers via an embedded Python library (google-auth), without looking at or needing your credentials in
	  the google-cloud-sdk
	* User-Managed Key (.json file): ~/some-folder/agremotesensing-a0e16021eb39.json
	* User-Managed Keys: typically show an expiration year of 9999 unless your organization enforces a custom 
	  key-expiration policy.
