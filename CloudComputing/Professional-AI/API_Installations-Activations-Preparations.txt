PART V

Create
	(ai-apis)				<== a separate, virtual environment in python for handling the AI APIs

Install into (ai-apis)
	spyder-kernels 			<== tools to allow Spyder access to the virtual environment
	google-genai 			<== most recent SDK for Google Gemini models
	openai					<== most recent SDK for OpenAI models
	jiter					<== A standalone version of the JSON parser
	nltk 					<== Natural Language Toolkit
###########################################################################

Notes: We will use Python to create a virtual environment called, (ai-apis).
The virtual environment will be created with the Python package, "venv"  using the command "venv". 
The virtual environment will be created in a sub-directory in Spyder. 
We will install special Python packages and SDK packages into the (ai-apis) virtual environment.



Create the virtual environment, (ai-apis)
--------
	- open a terminal in the "envs" directory of Spyder					<== Windows
	- enter the command line code
> C:\Users\<you>\AppData\Local\spyder-6\...\envs\> python3 -m venv ai-apis



	$ cd ~/spyder-6/envs 												<== MacOS
	$ python3 -m venv ai-apis



Activate the (ai-apis) virtual environment
-----------
	- open a terminal in the "ai-apis\Scripts" directory of Spyder				<== Windows
	- enter the command line code
C:\Users\<you>\...\spyder-6\...\envs\ai-apis\Scripts> activate
	
	- When activated, you will see (ai-apis) at the command line
(ai-apis)>

	- Keep this terminal open for the installation of special packages


		$ ~/spyder-6/envs													<== MacOS
		$ source ./ai-apis/bin/activate



Installation of special packages
---------
	- enter the command line code 										<== Windows
(ai-apis)> pip install spyder-kernels google-genai openai nltk jiter
	

	- enter the command line code 										<== MacOS
(ai-apis):~$ pip install spyder-kernels google-genai openai nltk jiter		



Deactivate and close the (ai-apis) virtual environment
----------
	- enter the command line code 										<== Windows
(ai-apis)> deactivate

	- When deactivated, you will no longer see (ai-apis) at the command line
>


	- enter the command line code 										<== MacOS
(ai-apis):~$ deactivate

	- When deactivated, you will no longer see (ai-apis) at the command line
$

PART VI

Set Spyder to run in the (ai-apis) virtual environment
###################################################

To work with a new (virtual) environment in Spyder, change the default Python interpreter for new IPython Consoles to point to this new environment. 
	


Open Spyder 6 and clic on the "wrench" in the toolbar to open the Preferences window
-----------
	- in left-hand column clic on "Python Interpreter"

	- in the right-hand window clic on the button "Use the following interpreter:"
		-- in the empty box search your compu directory until you find the (ai-apis) directory
			(.../spyder-6/envs/ai-apis)

		-- open this directory and find the Scripts (\Scripts) directory 		<== Windows

		-- open this directory and find the /bin (\bin) directory 				<== MacOS
	
		-- open the "Scripts" or "bin" directory and select a Python executable
		   (the "python3" icon)
			
		-- at the bottom of the window clic 'Apply' and then 'OK'

		-- close the "Preferences" window


	- back in the Spyder main windows, find the IPython interpreter window (bottom right)
		-- find the tab that says, "Console 1/a"

		-- close the tab by clicking on the "X"

		-- Spyder will (try to) re-start Python using the Python installed in (ai-apis)

			

Verify Spyder is operating in the (ai-apis) virtual environment
--------
	- if all good, you will see a green-colored "In [1]" in the IPython interpreter window (bottom right)

	- if an Error Box appears in the interpreter window something went wrong (try closing and re-opening Spyder)

PART VIII
Notes on
Prompt Engineering
##################

*You could think about developer and user messages like a function and its arguments in a programming language.
    -developer messages
    	provide the system's rules and business logic, like a function definition.

    -user messages 
    	provide inputs and configuration to which the developer message instructions are applied like arguments to a function.

	- a prompt 
		contains BOTH message types instructions: a) developer messages gives the model high-level instructions on how it should behave while generating a response, including tone, goals, and examples of correct responses. Any instructions provided this way will take priority over a prompt in the input parameter; b) user messages are strings of text, images, or file inputs to the model that are used to generate a specific response.
