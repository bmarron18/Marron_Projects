OLD SCRIPT REVIEW
###############
Both scripts are about getting raster/ASCII grid data (the `.asc` format used in GIS) into Python so you can work with it as arrays. They look like lab/coursework from 2016 (a FRAGSTATS landscape-metrics workflow, judging by the paths), and they're partly unfinished.

## ASCII_data1.py (ArcPy + NumPy)

**What it does:** Takes two ArcGIS rasters, builds an array of cell-centre coordinates, converts both rasters to NumPy arrays, and stacks everything into one array where each cell holds `[Y, X, value1, value2]`.

**Problems:**
- **The coordinate math is wrong.** `numpy.fromfunction` passes in *index grids* (row and column numbers), but the functions then add `rasHeight`/`rasWidth`, which are the grid *dimensions*, shadowing the arguments. The intended formula is:
  ```python
  coordX = rasXmin + (col_index + 0.5) * cellWidth
  coordY = rasYmin + (row_index + 0.5) * cellHeight
  ```
  As written, every cell gets the same constant offset, not a per-cell coordinate.
- **Parameter order is confused.** `fromfunction` calls the function with `(row_idx, col_idx)`, so the first argument is rows (Y direction) and the second is columns (X direction). The code names them the other way round, which is why the comment says "Y before X" and then has to explain `dstack` order.
- **Transposes look suspect.** `inRasterArray.T` swaps axes so the shape no longer matches the `(rows, cols, 2)` coordinate stack. It would raise a shape error unless the raster is square.
- **Dependency:** ArcPy requires a licensed ArcGIS install (the docstring notes this), so it won't run on a plain Python setup.

## ASCII_data2.py (GDAL / astropy)

**What it does:** Reads an ESRI ASCII grid (`.asc`) with GDAL, reports its size, band count and driver, then prints the geotransform (origin and pixel size).

**Problems:**
- **Python 2 syntax.** `print geotransform[0]` is a syntax error in Python 3. Use `print(geotransform[0])`.
- **Outdated import.** `from gdalconst import *` is deprecated; use `from osgeo import gdalconst`.
- **Unused/inconsistent bits:** the `astropy` read (`ascii.read`) points at a different file (`rck_crk06_rcl.asc`) than the GDAL one (`rck2_crk06_rcl.asc`), and astropy would not parse a georeferenced grid properly anyway. `ogr`, `osr`, `np` and `gdal_version` are imported/computed but never used.
- **It stops early.** It never reads the actual cell values; you'd want `dataset.GetRasterBand(1).ReadAsArray()` to get the data.
- Hardcoded absolute paths to a machine you probably no longer use.

## How I'd use them today

For the open-source route, a cleaned-up version of script 2 does what script 1 was trying to do, without ArcGIS:

<<< python
from osgeo import gdal
import numpy as np

gdal.UseExceptions()
ds = gdal.Open("your_file.asc")
gt = ds.GetGeoTransform()
band = ds.GetRasterBand(1)
arr = band.ReadAsArray()
nodata = band.GetNoDataValue()

rows, cols = arr.shape
col_idx, row_idx = np.meshgrid(np.arange(cols), np.arange(rows))
x = gt[0] + (col_idx + 0.5) * gt[1]
y = gt[3] + (row_idx + 0.5) * gt[5]   # gt[5] is negative for north-up rasters

stacked = np.dstack((y, x, arr))
>>>

Alternatively, `rasterio` is a friendlier modern wrapper around GDAL for this kind of work.
