**What it does**

- It extracts that run's partial text from `QueryResponse_Anthropic.txt`.
- It re-sends your files and prompt, then the partial text as the assistant's turn, then asks the model to continue exactly where it stopped, finishing any cut-off word or line first.
- It streams only the new text to `Resumed_Response_continuation.txt`, flushing every chunk.
- It writes `Resumed_Response_merged.txt`, which is the partial plus the continuation. This is written even if the run is interrupted.
- If the connection drops again, it retries up to 5 times and resumes from everything received so far.

**How the script gets there**

`extract_partial()` works in three steps:
1. It finds ` Run: 2026-11-06 10:53:11` in `QueryResponse_Anthropic.txt`.
2. It skips to the next line of 70 `=` characters (the end of the header).
3. It takes everything from there up to the next run header, or to the end of the file.

The "no reply text" error means steps 2 and 3 yielded nothing.

**Likely causes, most likely first**

1. **The original run died before the first chunk was written.** The header is written up front, so a connection failure before any streamed text leaves a header with nothing under it. In that case there is nothing to resume, and you should simply re-run v3.4.
2. **The stamp is the template default.** `RUN_STAMP` in the script is still `2026-11-06 10:53:11`. It was found, so a run with that time exists, but it may not be the run you meant. `--list-runs` will show you.
3. **The header layout differs from what the parser expects.** The parser assumes one `Run:` line, then a closing bar. If v3.4 writes extra lines (for example a Files: line, or another bar between them), it could stop at the wrong bar and extract the wrong slice.
4. **The file was overwritten.** If v3.4 ran in overwrite mode afterwards, the partial reply from the cut-off run may be gone.

**What the check does**
- `extract_partial()` looks for the `[REFUSED BY SAFETY SYSTEM ...]` block in the selected run, before it strips the bookkeeping lines or checks for empty text.

- The check runs on the raw text, so it also triggers when real reply text comes before the block. That happens when a later continuation pass is refused.
